Architecture

Moving away from Google Drive for file storage. The new stack:

  • Storage: Supabase S3 — private bucket, server-only access
  • Encryption: AES-256-GCM on raw text before DB insertion
  • Vectors: pgvector in Supabase, text-embedding-3-small
  • AI: RAG pipeline — decrypt in-session, embed, query
💡The key insight: decrypt only when an active session requests it. The raw text is never stored in plaintext — only the founder's session key can trigger decryption for AI reading.

Open Questions

Do we use nomic-embed-text (free, local) or text-embedding-3-small (OpenAI, better quality)? Leaning OpenAI for now — can switch later since pgvector is model-agnostic.

Vault v4 — Implementation Plan.md
Markdown · 8 min readVectorised
Internal · Apr 10, 2025·Kobin Engineering

Overview

This plan outlines the migration from Google Drive to a self-hosted, privacy-first storage architecture using Supabase Storage and AES-256 encryption. The goal is to eliminate external dependencies while enabling deep AI memory across all vault content.

New Capabilities

  • AI Deep Memory — Full-content semantic search. AI reads inside every PDF, Word doc, and note.
  • Zero-Knowledge Privacy — AES-256-GCM encrypted at rest. Raw text unreadable even to DB admins.
  • Turbo Uploads — Direct Supabase S3, up to 5× faster than Google Drive.
  • Secret Vaults (ACL) — Restrict files to specific team members via granular access control.
  • Instant Previews — No CSP frame errors. Files open from your own storage URLs.

Schema Changes

-- vault_items additions
ALTER TABLE vault_items ADD COLUMN storage_path TEXT;
ALTER TABLE vault_items ADD COLUMN is_internal BOOLEAN DEFAULT false;
ALTER TABLE vault_items ADD COLUMN permissions_mode TEXT DEFAULT 'public';
ALTER TABLE vault_items ADD COLUMN restricted_user_ids UUID[];

-- New: encrypted content store
CREATE TABLE vault_item_contents (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  vault_item_id UUID REFERENCES vault_items(id),
  encrypted_text TEXT NOT NULL,
  iv TEXT NOT NULL,
  auth_tag TEXT NOT NULL,
  created_at TIMESTAMPTZ DEFAULT now()
);
⚠️Important: The VAULT_MASTER_KEY environment variable must be a 256-bit random key generated with openssl rand -hex 32. Never commit this to version control.

Processing Pipeline

  1. File uploaded → Supabase Storage (private bucket)
  2. Text extracted (pdf-parse / mammoth / xlsx / plain text)
  3. Text chunked → embeddings via text-embedding-3-small
  4. Embeddings stored in vault_embeddings (pgvector)
  5. Raw text encrypted (AES-256-GCM) → stored in vault_item_contents
