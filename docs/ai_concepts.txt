# Founder-Assistant Repository Deep Analysis

## 1) Product Intent and Scope
Founder-Assistant (branded in-repo as **Kobin Ai / Comm Center**) is a full-stack operating system for founders. It combines:
- execution management (tasks/projects),
- relationship and revenue management (CRM),
- collaboration (team + inbox),
- client-facing delivery (client portal + vault), and
- AI-assisted operations (chat, tools, proactive summaries, risk alerts).

The architecture centers around a Next.js App Router frontend/server, Supabase data/auth/realtime, and Groq-powered AI orchestration. Most domain logic is server-driven through API routes under `app/api/*`.

## 3) AI Capabilities — Full Detailed Breakdown

### 3.1 AI Modes (Behavior Profiles)
Defined in `lib/ai/modes.ts`:
- **quiet**: suppresses morning/EOD chatter, only critical-risk style behavior.
- **balanced**: default operating mode, enables regular summaries + proactive reminders with higher risk threshold than aggressive.
- **aggressive**: maximum proactive behavior with lower threshold for risk alerts.

Each mode controls:
- morning briefing behavior,
- EOD summary behavior,
- risk alerting and threshold,
- inbox intelligence behavior,
- proactive follow-up reminders.

### 3.2 AI Read Tooling (Context Retrieval)
Defined in `lib/ai/mcp-read-tools.ts`:
- `get_workspace_overview`
- `get_tasks`
- `get_projects`
- `get_team_workload`
- `get_crm_pipeline`
- `get_calendar`
- `get_vault_files`
- `get_task_creation_context`
- `search_contacts`
- `get_meeting_notes`
- `vault_semantic_search`

**Why this matters:** the AI avoids huge static prompts and instead performs selective retrieval to reduce hallucination and keep responses current.

### 3.3 AI Action Tooling (Execution Layer)
Defined in `lib/ai/tools.ts`, executed via `lib/ai/action-executor.ts`:
- `create_task`
- `update_task`
- `delete_task`
- `create_project`
- `update_project`
- `search_messages`
- `update_deal_stage`
- `send_message_to_room`
- `analyze_workspace`

Execution engine capabilities include:
- fuzzy resolution of human names/project names,
- due-date-aware smart bucket inference,
- vault attachment resolution by fuzzy title,
- normalization of enum and boolean-like inputs,
- confirmation handshakes for destructive/sensitive actions.

### 3.4 Workspace Intelligence Engine
Defined in `lib/ai/intelligence.ts`:
- Detects **overdue tasks**, **blocked tasks**, **stale deals**, **overloaded team members**, and **at-risk projects**.
- Assigns severity (`critical`, `high`, `medium`) based on timing, value, and load.
- Produces ranked priorities and bottleneck narrative statements.
- Produces team-load snapshots (FREE/LIGHT/MODERATE/HEAVY).
- Returns structured intelligence payload with generation timestamp.

### 3.5 Proactive AI Communication Layer
Defined in `lib/ai/proactive.ts`:
- Ensures dedicated AI chat room existence per founder.
- Posts AI-originated messages with model metadata and AI message typing.
- Sends web-push notifications alongside inbox insertion.
- Generates:
  - **Morning Brief** (top priorities/focus),
  - **Risk Alert** (event-driven warning),
  - **End-of-Day Summary** (progress + next-priority guidance).

### 3.6 RAG / Semantic Vault Intelligence
Supporting files: `lib/ai/vault-rag.ts`, `lib/ai/embeddings.ts`, `lib/ai/chunking.ts`, vault API endpoints.

Capabilities:
- document chunking for embedding pipelines,
- semantic similarity retrieval across vault corpus,
- vault-aware contextual grounding for AI responses,
- project-scoped document retrieval for precise operational answers.

### 3.7 AI Endpoint Capabilities (Operational Surface)
Under `app/api/ai/*`:
- analysis endpoints (generic and email-specific),
- conversational chat endpoint,
- command-oriented endpoint,
- proactive trigger endpoint,
- task extraction endpoint,
- draft reply endpoint,
- warmup endpoint for readiness/performance.

### 3.8 AI + Meeting Intelligence
Meeting bot pipeline feeds AI workflows:
- audio/transcript processing,
- post-meeting structuring,
- retrieval of meeting notes/decisions/action items,
- CRM/task follow-through opportunities.

### 3.9 AI Safety and Reliability Patterns Present in Code
- Explicit tool schemas + typed argument constraints.
- Separation of read vs write tooling.
- Name resolution and normalization before writes.
- Confirmation flags for destructive/high-impact actions.
- Caching around expensive intelligence queries.

## 4) Summary: What This Repo Delivers
This repo is not a single-feature app; it is a **multi-role operating platform** with:
1. founder operations cockpit,
2. team execution workspace,
3. client-facing portal,
4. integrated communications + CRM + knowledge vault,
5. embedded AI chief-of-staff system with both reactive and proactive behavior.

The AI layer is substantive: it includes retrieval tools, mutation tools, intelligence scoring, proactive briefs, and semantic vault search — not just prompt wrappers.
